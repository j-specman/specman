Aus aktueller Anwendung
- Hat man 5 Sekunden Autosave-Intervall eingestellt, dann wird es auffällig, dass ein abhängendes Leerzeichen wegbereinigt wird.
   Wenn der User aber grade editiert, dann ist das eine häufige Situation, und dem User gehen ständig Leerzeichen verloren.
- Durchgestrichen kann der User als Schriftformatierung auswählen. Da beißt sich aber mit Durchstreichungen durch den Änderungmodus
  - Führt z.B. zu Fehlern, wenn man Text durchstreicht, den entsprechenden Schritt dann löscht und dann die Änderungen zurücknimmt
  x Durchgestrichen ist als Workaround als Schriftformatierung nicht mehr auswählbar (siehe HTMLEditorPane, HTML.Tag.STRIKE)
- beim Öffnen und einer vorhandenen .wrk, *drei* Optionen: 1) nicht laden, 2) laden, 3) ist in Arbeit - nicht laden aber auch nicht überschreiben und beim Schließen löschen
- Beim Suchen wird die gefundene Stelle im Text nicht markiert. Könnte allerdings ein reines Linux-Problem sein.
- PDF-Option "Export beim Speichern"

Globale Links:
x Custom URL Scheme, z.B. specman://uc730,2d34f85e,1.3
  x Bewusst nicht so URL-typisch wie specman://open?file=uc-730&step=2d34f85e&number=1.3, weil das schlechter lesbar ist
x Über neuen Kontextmenüpunkt "Copy Link" an der Schrittnummer kann man die URL in die Zwischenablage kopieren
x Ausgegraut, wenn das Modell noch nicht gespeichert wurde, weil man dann noch keinen Dateinamen hat
x Beim ersten Mal in einer Datei, erscheint ein Dialog mit dem Vorschlag, einen Alias für Links auf diese Datei anzulegen
  x Dialog bietet ein Textfeld für den Alias, nur ASCII-Buchstaben, Zahlen, Unterstriche, Gedankenstriche, maximal 20 Zeichen
  x Darunter sieht man die URL, bei leerem Alias wird der Dateiname verwendet, also z.B. specman:///C:/project/UC-720%20Eins%20Zwei.nsd,2d34f85e,1.3
  x Komma im Dateinamen muss als %2C kodiert werden, damit das Komma als Trennzeichen zur Schritt-ID und Schrittnummer eindeutig erkennbar ist.
  x Ändern des Alias ist jederzeit möglich, dann ändert sich auch die URL
  x Hinweis, dass man die Aliasse jederzeit über Datei -> Alias ändern kann
  x Zuordnung von Alias zu Datei wird in den User Preferences abgelegt, wenn der User OK drückt
  - Idee der Aliasse für Team-Kollaboration und Pfadunabhängigkeit der Links muss im Manual erklärt werden.
  x OK geht nur, wenn der Alias case-insensitiv eindeutig oder leer ist
  x Cancel sorgt dafür, dass nichts in der Zwischenablage landet und auch keine Zuordnung in den User Preferences abgelegt wird
  x Eine leere Eingabe wird ebenfalls in den User Preferences abgelegt, um zu verhindern, dass der Dialog bei jedem Öffnen der Datei wieder erscheint
x Aus der Zwischenablage kann man den Link anschließend in beliebige andere Tools einfügen
x Schrittnummer in der URL ist nur informativ, kann entfallen
x Schritt-ID kann in der URL entfallen, dann adressiert die URL nur die Datei und keinen Schritt darin
x Über Datei -> Alias: Dialog mit allen Dateien, für die ein Alias definiert ist, jeweils Alias und Datei mit Pfad.
  x Aliasse sind editierbar - Einschränkungen s.o.
  x Nicht mehr existierende Dateien sind als verwaist markiert. Der User kann die Datei wieder neu auswählen
  x Zeilen können auch gelöscht werden
  x Über Abbrechen können die Änderungen verworfen werden
  x Speichern geht nur, wenn die Aliasse case-insensitiv eindeutig sind (ausgenommen alle leeren Aliasse)
x Bei "Speichern unter..." bleibt ein etwaiger bereits zugeordneter Alias mit der alten Datei assoziiert.
  x Der User muss ggf. die Zuordnung zur neuen Datei über Datei -> Alias selbst nachtragen.
x Einfache Navigation über einen Link
  x Link aus irgendeinem Quelldokument in die Zwischenablage kopieren
  x User startet Specman bzw. klickt ein laufendes Specman an und löst mit STRG+L das Navigieren zum Link in der Zwischenablage aus (STRG+L als Shortcut für einen Menüpunkt)
  x URL parsen (bedenken: Copy aus Quelldokument könnte einen Slash hinten ergänzt haben)
  x Wenn Datei nicht gefunden: Fehler
  x Wenn Alias, Datei über die User Preferences auflösen
  x Wenn der Alias unbekannt ist: Dialog für eine on-the-fly Dateizuordnung
  x Datei öffnen, wenn nicht schon geöffnet, ggf. in der URL adressierten Schritt suchen und den Fokus darauf setzen
    x Ist der Schritt unbekannt, Toast-Feedback, dass der Schritt nicht gefunden wurde
    x Schritt wird über die ID adressiert, nicht über die Schrittnummer, weil die sich ja ändern kann
    x Toast-Feedback, wenn die Schrittnummer in der URL nicht mehr mit der ID übereinstimmt
    x Bei einem verschobenen Schritt trägt der Zielschritt die ID - das ist genau richtig.
- Integration der Navigation ins Betriebssystem kommt später. Grundprinzip
  - Unter Windows: Eintragen des specman-Protokolls in der Windows Registry
  - Betriebssystem startet auf dieser Basis Specman, danach wie oben beschrieben
  - Besonderheit: Wenn schon eine andere Specman-Instanz läuft, das die Datei geöffnet hat, dann wird die Datei nicht nochmal geöffnet,
    - Stattdessen Fokus auf das bereits geöffnete Fenster setzen und zum ggf. in der URL adressierten Schritt navigieren
    - Das ist anspruchsvoll, weil es Interprozess-Kommunikation erfordert.
x Nice to have: Dialog für Alias-Vergabe schlägt initial einen Alias vor, wenn sich aus den bereits in den User Preferences abgelegten Aliasse ein Muster ablesen lässt, das auch auf die aktuelle Datei anwendbar ist
  x Beispiel: es liegt bereits vor: Alias "uc730" für Datei "C:/project/BALI UC-730 Kundendaten pflegen.nsd"
  x Dann sind alle Zeichen des Alias von links nach rechts im Präfix der Datei enthalten, und ergeben sich durch Auslassung bestimmter Zeichenfolgen.
  x Quasi aus dem regulären Ausdruck: ".{16}(.{2}).{1}(.{3}).*" -> Alias = $1$2
  x Eine aktuelle Datei "C:/project/BALI UC-135 Was Anderes.nsd" erfüllt diesen Ausdruck ebenfalls, und der Alias ergibt sich zu "uc135"
  x Ausschlaggebend ist der Treffer mit dem längsten Alias, bei mehreren der erste (nur Zuordnungen aus demselben Verzeichnis)
  x Vorschlag nur, wenn der abgeleitete Alias eindeutig ist
  x Ganz genaues Verfahren inkl. genauer Umgang mit Groß/Kleinschreibung wird im Rahmen der Umsetzung geklärt
  x Details könnten tricky sein, deswegen nicht Teil der ersten Ausbaustufe
x Nice to have: Dialog für eine on-the-fly Dateizuordnung schlägt Datei vor, wenn sich aus den bereits in den User Preferences abgelegten Aliasse ein Muster ablesen lässt, das auch auf die aktuelle URL anwendbar ist
  x Quasi in umgekehrter Richtung für den Vorschlag eines Alias oben bei Aliasvergabe.
    x Aus einer bestehenden Zuordnung das Verzeichnis der Datei extrahieren
    x Den regulären Ausdruck für die Ableitung des Alias ableiten
    x Dann im Verzeichnis nach Dateien suchen, die den regulären Ausdruck erfüllen, der sich aus dem Alias des Links ergibt
    x Ganz genaues Verfahren wird im Rahmen der Umsetzung geklärt
  x Details könnten tricky sein, deswegen nicht Teil der ersten Ausbaustufe
- Nice to have: Nutzung der Links auch als Hyperlinks in Schritttexten, um von einer Spezifikation auf eine andere zu verweisen.

Abschluss für Go-Live
- Wenn man zu einem Breakschritt bzw. einem Catch-Bereich springt oder einer Schrittreferenz folgt, dann kann sich das Ziel
   der Navigation in einem zusammengeklappten Bereich befinden. Was machen wir dann? Aufklappen?
- Wenn man aus einem Break-Schritt heraus einen neuen Schritt anlegt, dann ist das keine atomare Operation.
   Der BreakSchritt hat einen Fokus-Listener, der beim Fokusverlust den Inhalt des Steps (unnötig) neu aufbaut, und
   das liegt nicht in der Undo-Composition für die Neuanlage.
- Redo einer Schrittverschiebung im Änderungsmodus funktioniert nicht, wenn Ziel und Quelle der Verschiebung nicht in der
   gleichen Sequenz liegen.
       Exception in thread "AWT-EventQueue-0" java.lang.IllegalArgumentException: Step 2.1 -
       Neuer Schritt 1 is not part of sequenz specman.view.SchrittSequenzView@799d4085
        at specman.view.SchrittSequenzView.stepIndex(SchrittSequenzView.java:282)
        at specman.view.SchrittSequenzView.insertStep(SchrittSequenzView.java:289)
        at specman.undo.UndoableSchrittVerschobenMarkiert.redoEdit(UndoableSchrittVerschobenMarkiert.java:33)
- Wenn man einen Schritt aus einer Sequenz ohne abgesetzte Darstellung in eine Sequenz *mit* abgesetzter Darstellung zieht,
   dann erhält der EditContainer des Schritts dabei nicht die notwendigen Insets. Nach Speichern und Laden ist natürlich alles OK.
   Gleiches in der anderen Richtung.
- Wenn beim Split einer TextEditArea der *vordere* Textteil überflüssige Whitespaces enthält,
   dann wird der hintere Teil falsch kopiert. Für das Herstellen des hinteren Textteils wird nämlich intern zuerst der *ganze* Text
   kopiert und anschließend gekürzt. Das Kopieren bewirkt die Bereinigung, sodass die ursprüngliche Caret Position im kopierten Text
   nicht mehr sauber den Index repräsentiert, bis wohin der vordere Textteil in der Kopie abgeschnitten werden muss.
- Kleine, eigenartige Macke: Wenn man als allererste Operation nach dem Öffnen einer Datei einen neuen Textparagraphen einfügt, dann
   funktoniert das Undo dafür nicht. Macht man davor (oder auch danach!) irgendeine andere rücknehmbare Operation, dann funktioniert es
- List Items als EditAreas
  - Korrekte Begriffe in Combobox für ordered und unordered LI
  - Saubere Darstellung des Labels
    - Vertikal, nicht nummeriert: Mitte der ersten Zeile abhängig von der Zeilenhöhe - hängt von der größten Schrift in der ersten Zeile ab (-> JEditorPaneUtilities)
    - Vertikal, nummeriert: Baseline der ersten Zeile (-> JEditorPaneUtilities)
    - Horizontal: zoom-abhängiger rechter Abstand (sorgt für rechtsbündig bei nummeriert)
    - Wie groß machen wir die Schrift für Nummernlabel? In Word gibt's Regeln. Am besten erstmal: Standardgröße
    - Wie darstellen, wenn man im Änderungsmodus LI zu normalem Text macht
  x Unterscheidung nummeriert / nicht nummeriert
  x Undo / Redo für LI anlegen und LI entfernen
  - Irgendeine Idee für mehrstufige LIs?
- Reste der Überarbeitung der Darstellung von Catch-Bereichen
  - Unterstützen wir abgesetzte Darstellung? Wäre nicht schlecht. Aber wie schaltet man um? Der Catchbereich selbst hat keinen Text.
    - Darf nur unter den letzten Schritt einer Sequenz gedragged werden.
  - Break-Schritte dürfen (noch) nicht in Catch-Sequenzen eingefügt werden. Vielleicht sollten wir insgesamt zunächst nur
     Einfache Schritte zulassen
  - Wenn es in der CatchUeberschrift beim Größer- und Kleinerschieben zu Veränderungen der Höhe durch Zeilenumbrüche kommt, geht manchmal

  - Übertragung einer Inhaltsänderung bei FocusLost kommt als separate Aktion in die Undo-Historie. Das ist nicht schön
